# P9.1: whole-brain benchmark baseline

The benchmark suite is [`scripts/benchmark_whole_brain.py`](../scripts/benchmark_whole_brain.py).
It measures the public `heldout_forward.build_multi_target_model()` path at
all three supported parcellation resolutions and with one, three and five
receptor systems. Each row includes model construction, one drug-free steady
state, and one active steady-state evaluation. The active input is `x = 0.1`
for every requested target; this is a timing workload, not a pharmacological
claim.

The machine-readable outputs are
[`p9_1_benchmark.csv`](../results/benchmarks/p9_1_benchmark.csv),
[`p9_1_benchmark.json`](../results/benchmarks/p9_1_benchmark.json), and
[`p9_1_profile.txt`](../results/benchmarks/p9_1_profile.txt). The run used the
cached published Knox 2019 connectome and Allen expression atlas, Python
3.12.3, NumPy 2.4.6, and Linux 6.8.0-134-generic-x86_64. Timings are
machine-specific baselines, not model parameters.

The 291-region, five-target case is the relevant current whole-brain upper
baseline: one construction plus one active solve takes 4.36 seconds in this
environment. The dense connectivity matrix occupies 677,448 bytes at that
resolution; the benchmark records this separately because sparse storage is a
P9.2 design question, not a timing assumption.

## Where the time goes

The representative five-target, 291-region profile took 2.937 seconds. Its
largest cumulative-time regions were:

- `circuit_forward.steady_state_rates`: 1.542 s across the baseline and active
  integrations.
- `network.CircuitNetwork.rhs`: 1.460 s over 328 RHS calls.
- `circuit.sigmoid`: 1.224 s over 95,448 calls; NumPy clipping inside that path
  accounts for 0.889 s.
- model construction: 1.315 s, including 0.628 s loading the cached Knox
  inputs, 0.356 s in `stability.stabilize`, and 0.149 s loading expression.
- `numpy.linalg.svd` inside stabilization: 0.348 s over three contraction-
  number evaluations.

These numbers establish the optimization order. The active solve is dominated
by repeated dense RHS evaluation and scalar sigmoid/clipping work, so P9.2
should benchmark sparse/stiff integration and P9.3 should benchmark a
vectorized RHS and steady-state path. Connectome parsing and stabilization are
construction costs; caching or reusing the stabilized network can address
those separately, but it must not be confused with a faster solver.

## Interpretation and limits

The benchmark does not claim that five receptor systems are the final model,
that the illustrative operating point is calibrated, or that one active solve
is a representative scientific simulation. It fixes a repeatable workload and
records the exact source, resolution, node/edge counts and target set so later
numerical changes can be compared against the same baseline. Any P9.2/P9.3
speedup must also compare rates against this RK45 reference within an explicit
accuracy tolerance.
