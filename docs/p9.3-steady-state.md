# P9.3: vectorized RHS and direct steady-state solver

`CircuitNetwork.rhs()` now broadcasts node gains, thresholds and time
constants through NumPy arrays. `rhs_reference()` retains the former
node-by-node implementation as a regression oracle. The circuit forward path
also exposes `steady_state_root()`, which solves the same RHS fixed-point
equations with SciPy's hybrid root solver and the analytic circuit Jacobian.

The reproducible benchmark is
[`benchmark_steady_state.py`](../scripts/benchmark_steady_state.py). It repeats
P9.1's nine workloads: one, three and five target layers at all three
connectome resolutions. The integration-vectorized path uses the existing
30-time-constant horizon and tolerances. The root-jacobian path starts from
the cached drug-free state for active workloads. Results are committed in
[`p9_3_steady_state.csv`](../results/benchmarks/p9_3_steady_state.csv) and
[`p9_3_steady_state.json`](../results/benchmarks/p9_3_steady_state.json).

## Representative results

Seconds on the recorded Linux/Python 3.12 environment. Speedup is against
the matching P9.1 solve; error is maximum absolute rate difference from the
vectorized integration result.

| Resolution | Targets | Workload | P9.1 | Vectorized integration | Root + Jacobian | Root error |
|---|---:|---|---:|---:|---:|---:|
| regions (291) | 1 | active | 0.812 | 0.033 (24.7×) | 0.069 (11.8×) | 4.6e-10 |
| regions (291) | 5 | active | 1.660 | 0.124 (13.4×) | 0.218 (7.6×) | 1.1e-09 |
| subdivisions (60) | 5 | active | 0.191 | 0.038 (5.1×) | 0.028 (6.9×) | 2.0e-09 |
| major divisions (12) | 5 | active | 0.067 | 0.022 (3.0×) | 0.004 (17.7×) | 2.6e-09 |

Across all 18 vectorized-integration rows (baseline and active), the speedup
over P9.1 is 1.8× to 43.3×. Across all 18 root rows, every maximum absolute
error is below `7e-9` as recorded; all are below the `1e-6` fixed-point
tolerance.

The root solver is therefore available through
`steady_state_rates(..., solver="root")`, and the whole-brain `rates()` APIs
forward the same option. It is not made the universal default: vectorized
integration is faster for the largest five-target workload and remains the
trajectory-preserving compatibility path, while root is valuable when a
direct fixed point is preferred or for workloads where its measured speed
advantage is clear.
